# Google Play IAP для Laser Hero

В проект установлен Unity IAP 5.4.4. В магазинах лазеров и аур под обычным действием есть ярко-фиолетовая кнопка оплаты. Она показывает только число, например `0.99`. Товары постоянные, тип Unity IAP — `NonConsumable`.

## Где менять настройки

Открой в Unity `Assets/LaserHero/Settings/GooglePlayCatalog.asset`. У каждого элемента есть `kind`, `index`, `productId` и `previewPrice`. Это единый каталог для сервиса оплаты и интерфейса.

`previewPrice` задаёт цену предпросмотра. Реальную цену нужно выставить в Google Play Console. После подключения игра подставляет числовую `localizedPrice`, полученную из Google Play. Валюта и окончательная сумма также показываются стандартным окном оплаты Google.

## Что ещё нужно сделать в Google Play

1. Создать приложение и выбрать собственный Android package name. Сейчас в проекте остаётся шаблонный `com.UnityTechnologies.com.unity.template.urpblank`; заменить его в Player Settings → Android → Identification на ID своего приложения.
2. Настроить платёжный профиль разработчика и создать one-time products с ID из таблицы. Задать реальные цены и активировать товары/варианты покупки. Product ID должны совпадать с каталогом. [Создание товаров — Google](https://support.google.com/googleplay/android-developer/answer/1153481?hl=en).
3. Взять публичный лицензионный ключ приложения из Play Console и вставить в `googlePlayPublicKey` каталога. Это ключ проверки подписи Google Play-чеков; без него запуск оплаты заблокирован.
4. Подготовить подписанный Android App Bundle с тем же package name и загрузить во внутреннее тестирование. Добавить Google-аккаунты в License testing и список тестировщиков приложения. [Настройка тестировщиков — Google](https://support.google.com/googleplay/android-developer/answer/6062777?hl=en-419).
5. На Android проверить успешную покупку, отмену, отказ оплаты, отложенную оплату и восстановление после переустановки. Подтверждённый постоянный предмет нельзя купить повторно. Использовать лицензионных тестировщиков для тестовых платежей. [Сценарии проверки Google Play Billing](https://developer.android.com/google/play/billing/test).

В Unity Editor и Windows Standalone автоматически подключается штатный Unity Fake Store. В Play Mode фиолетовая кнопка открывает окно Fake Store: Buy выдаёт и сохраняет предмет, Cancel отменяет покупку. Денег это не списывает, ключ Google Play не нужен. Тестовые предметы остаются в текущем сохранении; для старта с нуля используй «Сброс прогресса». Windows-сборки используют симуляцию Unity Fake Store с окнами Buy/Cancel, без реальных списаний. Android использует Google Play и проверку подписи; тестовые чеки там не принимаются. На остальных платформах покупки отключены. После изменения кода Windows-приложение нужно пересобрать. Реальные платежи в этой работе не выполнялись: приложение, товары и ключ Google Play пока не созданы.

## Выдача и сохранение

- Product ID сопоставляется с индексом лазера или ауры в каталоге.
- В `OnPurchasePending` локальный Google Play-валидатор проверяет подпись, product ID, transaction ID и статус покупки.
- Лазер открывается через бит `LaserSave.ownedLasers`, аура — через `ownedAuras`. Новая покупка также надевает предмет. Восстановление сохраняет выбранную экипировку.
- Выдача и журнал `iapTransactions` сохраняются существующим `LaserProgress.Save()` / `PlayerPrefs.Save()` **до** `ConfirmPurchase`. Существующее сохранение YG также получает обновлённый JSON, если его SDK включён.
- Запись `transaction ID:product ID` и битовые права не дают повторно начислить награду. Неудачная проверка или сохранение не подтверждают заказ: он может прийти повторно.
- При отложенной оплате предмет не выдаётся. Отмена/ошибка оплаты возвращает возможность повторить попытку.
- При старте после получения товаров запрашиваются прежние покупки; в обоих магазинах есть кнопка «Восстановить».
- Используется локальная проверка чеков; отдельный сервер оплаты не подключён.

Механика соответствует [двухэтапному потоку Unity IAP](https://docs.unity.com/en-us/iap/purchases).

## Изменённые файлы

- `Assets/LaserHero/Runtime/LaserStoreCatalog.cs`: редактируемые товары, цены предпросмотра и проверка каталога.
- `Assets/LaserHero/Runtime/LaserIAPStore.cs`: Google Play, выдача, проверка чеков, подтверждение, восстановление и ошибки.
- `Assets/LaserHero/Runtime/LaserProgress.cs`: журнал обработанных транзакций и совместимость старых сохранений.
- `Assets/LaserHero/Runtime/LaserHeroHUD.cs`: вторые кнопки покупки, увеличенные карточки и восстановление.
- `Assets/LaserHero/Editor/LaserIAPSetup.cs`: создание каталога и подключение сервиса к сцене, подсказки Inspector.
- `Assets/LaserHero/Editor/LaserIAPVerification.cs`: проверки каталога, выдачи, повторной доставки, сохранения и интерфейса.
- `Packages/manifest.json`, `Packages/packages-lock.json`: изменения Unity Package Manager при установке пакета.

Сцена Lobby сохранена. Резервная копия: `Assets/Scenes/Backups/Lobby_BeforeGoogleIAP.unity`. Снимки: `LaserHero-IAP-Lasers.png`, `LaserHero-IAP-Auras.png`; результат проверок: `IAP-Verification.txt`.

76 проверок каталога, соответствия наград, повторной выдачи, журнала сохранения, числовых цен, готовности тестового магазина в Editor и расположения кнопок прошли. Визуально проверены обе витрины.
